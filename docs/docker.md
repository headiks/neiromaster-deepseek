# НейроМастер в Docker

## Запуск — одна команда

```bash
docker compose up -d
```

Нужен только Docker (Compose v2.24+). Node.js, Python, PostgreSQL на машине не нужны —
всё собирается и работает в контейнерах. Первый запуск собирает образы (worker с docling —
дольше всего), дальше старт занимает секунды.

При первом старте само создаётся:

- схема обеих БД и миграции;
- ключ шифрования ПДн (том `secrets`);
- учётка суперадмина — логин и пароль в логе:

```bash
docker compose logs web | grep -A3 "главного администратора"
```

Сайт: **https://localhost** (или адрес из `SITE_ADDRESS`). Для `localhost` и IP-адреса
сертификат выпускает внутренний CA Caddy — браузер один раз предупредит, это ожидаемо.

## Что внутри

| Контейнер | Назначение |
|---|---|
| `caddy` | вход снаружи: HTTPS (порты 80/443) → `web`. Единственный с портами наружу |
| `web` | API и сайт (gunicorn + uvicorn). При старте — схема БД и миграции |
| `worker` | разбор документов (docling) и генерация через DeepSeek, очередь RQ. Процессов внутри — по железу |
| `db-processed` | основная БД: всё, что получено обработкой (разделы, разметка, планы, сообщения), и рабочие данные (пользователи, сессии, журнал) |
| `db-raw` | исходники: оригиналы документов и загруженные штатки — байт в байт. Штатки зашифрованы ключом ПДн |
| `redis` | очередь задач и общий стейт процессов |
| `web-demo`, `worker-demo`, `db-demo` | демо для показа клиентам: свой сайт (`DEMO_SITE_ADDRESS`), своя PostgreSQL, свои тома. S3 и `db-raw` в демо выключены — к данным клиентов доступа нет. См. «Демо» ниже |
| `embed` | векторы вопросов для базы готовых ответов: bge-m3 на CPU (llama.cpp). Модель ~600 МБ скачивается при первом старте в том `models-llm`, дальше работает без интернета. Недоступен — база ответов ищет только точные совпадения |

Из `db-raw` всегда можно заново получить содержимое `db-processed` (переобработка), поэтому
`db-processed` — то, что переносится в закрытый контур, а `db-raw` может остаться в контуре
обработки.

## Настройки

Необязательный файл `.env` рядом с `docker-compose.yml` (образец — `.env.example`). Без него
всё стартует со значениями по умолчанию. Основное:

| Переменная | По умолчанию | Что это |
|---|---|---|
| `DEEPSEEK_API_KEY` | — | ключ модели; без него разбор документов и ответы ассистента не работают |
| `SITE_ADDRESS` | `localhost` | домен (сертификат Let's Encrypt, нужен интернет) или IP (внутренний CA) |
| `POSTGRES_PROCESSED_PASSWORD`, `POSTGRES_RAW_PASSWORD` | `neiromaster`, `neiromaster_raw` | пароли БД. **Задайте до первого запуска** — потом их меняют через `ALTER USER` |
| `NEIROMASTER_ADMIN_PASSWORD` | сгенерируется | начальный пароль суперадмина, от 8 символов |
| `NEIROMASTER_DEEPSEEK_BUDGET` | наибольший виденный баланс | сколько считать за 100% в полосе «Баланс DeepSeek» у суперадмина |
| `DEMO_SITE_ADDRESS` | `demo.localhost` | адрес демо, например `demo.example.ru` (DNS — на этот же сервер) |
| `POSTGRES_DEMO_PASSWORD` | `neiromaster_demo` | пароль БД демо. Задайте до первого запуска |
| `DEMO_PASSWORD`, `DEMO_OWNER_PASSWORD` | `demo12345`, сгенерируется | пароль демо-учёток; пароль суперадмина демо-экземпляра |
| `WEB_CONCURRENCY`, `NEIROMASTER_RQ_WORKERS`, `NEIROMASTER_DB_POOL`, `NEIROMASTER_PUSH_WORKERS` | по железу | процессов web, RQ-воркеров, пул БД, потоков отправки пушей. Сервер считает сам по ядрам и памяти (`backend/sizing.py`, итог — в логе `[sizing]`); задавайте, только чтобы переопределить |
| `HTTP_PORT`, `HTTPS_PORT` | `80`, `443` | порты на хосте |

БД и Redis наружу не публикуются — доступны только контейнерам приложения.

## Компании и роли

Один сервер обслуживает много компаний-клиентов. У каждой — своя схема в PostgreSQL
(`cab_<код>`: люди, документы, планы, сообщения, вопросы, журнал), своя папка файлов
(`data/documents/cab_<код>/`), свой префикс в S3 и `db-raw`, свой кэш ответов в Redis.
Вход — по одному адресу: логины уникальны во всей системе, сервер сам находит компанию.

| Роль | Кто | Что может |
|---|---|---|
| Суперадмин | мы (одна учётка, создаётся при первом старте) | раздел «Компании»: создаёт компании и их администраторов, видит сводку по всем компаниям, журнал действий всех компаний и баланс DeepSeek |
| Администратор | один на компанию, его создаёт суперадмин | всё внутри своей компании; заводит кураторов и сотрудников |
| Куратор | заводит администратор, у куратора обязательно есть отдел | документы, планы и сотрудники своего отдела; заводит только сотрудников в свой отдел |
| Сотрудник | заводит администратор или куратор | свой план, сообщения, вопросы ассистенту |

Компанию создают в интерфейсе («Компании» → «Новая компания»): логин и временный пароль
администратора показываются один раз, при первом входе он задаёт свой. То же из консоли:

```bash
docker compose exec web python backend/provisioning.py romashka --company "ООО Ромашка" --admin "Иванов Иван Иванович"
docker compose exec web python backend/provisioning.py --list
```

Данные, заведённые до разделения на компании, остаются у суперадмина (схема `public`);
прежние администраторы отделов при обновлении становятся кураторами. Самостоятельная
регистрация по умолчанию выключена (`NEIROMASTER_ALLOW_REGISTRATION=1` — включить).

## Демо

Отдельный экземпляр для показа клиентам — `web-demo`, `worker-demo`, `db-demo` — стартует
той же командой `docker compose up -d`. Адрес — `DEMO_SITE_ADDRESS` (на сервере —
`demo.<домен>`, DNS-запись на этот же сервер; локально — https://demo.localhost).

При первом старте сама создаётся «Демо-компания»:

- учётки (пароль — `DEMO_PASSWORD`, по умолчанию `demo12345`, показываются на странице входа):
  `demo` — администратор, `demo-curator` — куратор отдела «Производство»,
  `demo-employee` — сотрудник (водитель, выходит сегодня);
- документы из `data/demo/` и `examples/` (разбирает `worker-demo`, нужен `DEEPSEEK_API_KEY`);
- быстрые уведомления: после назначения плана сотруднику первые 5 сообщений приходят
  каждые 30 секунд, остальные — с промежутками плана.

Свои демонстрационные документы положите в `data/demo/` до сборки образа. Сброс демо в
исходное состояние (всё, что создали посетители, удаляется):

```bash
docker compose exec web-demo python backend/demo.py reset
```

Суперадмин демо-экземпляра — свой (логин и пароль — в `docker compose logs web-demo`).
Демо не нужно — `docker compose up -d web worker caddy` (или удалить три службы демо).

## Обновление

```bash
git pull && docker compose up -d --build
```

Миграции схемы применяются сами при старте `web`; worker стартует после него.

## Бэкап

```bash
docker compose exec -T db-processed pg_dump -U neiromaster -Fc neiromaster > processed.dump
docker compose exec -T db-raw pg_dump -U neiromaster_raw -Fc neiromaster_raw > raw.dump
docker compose cp web:/app/data/secrets/pii.key ./pii.key   # хранить ОТДЕЛЬНО от дампов
```

Без `pii.key` зашифрованные ФИО, контакты и штатки не восстановить. Дамп `db-processed`
включает все компании (каждая — своя схема); одну компанию можно выгрузить отдельно:
`pg_dump -U neiromaster -Fc -n cab_<код> -n public neiromaster`.

## Закрытый контур (без интернета)

На машине с интернетом собрать образы и упаковать их в архив:

```bash
docker compose build
docker save neiromaster-web neiromaster-worker postgres:16-alpine redis:7-alpine caddy:2-alpine \
  | gzip > neiromaster-images.tar.gz
```

В закрытом контуре — репозиторий (или только `docker-compose.yml` и `deploy/`) и архив:

```bash
docker load < neiromaster-images.tar.gz
docker compose up -d
```

Образы уже есть локально — compose ничего не скачивает и не собирает.

## Переезд с установки через install.sh

1. Дамп старой БД → в `db-processed`:
   `docker compose exec -T db-processed pg_restore -U neiromaster -d neiromaster --clean < old.dump`
2. Ключ ПДн → в том секретов: `docker compose cp data/secrets/pii.key web:/app/data/secrets/pii.key`
3. Оригиналы документов → в `db-raw`: скопировать `data/documents/` в контейнер и выполнить
   `docker compose exec web python backend/rawdb.py --backfill` (идемпотентно; берёт и из S3, если он настроен).
