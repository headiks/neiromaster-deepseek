## Блок 1. База знаний для всех планов адаптации

**Как устроено сейчас (важно):** база знаний = чанки документов, размеченные по подэтапам
каталога (`data/stage_catalog.json`), общая для всех планов. План — это набор подэтапов.
Генерация текстов работает под **любой** план: `POST /plans/{id}/generate` и
`/generate-missing` ([api_plans.py](../api_plans.py)). Отдельная «генерация для
пользовательских планов» не нужна — нужны триггеры, чек-суммы и наглядность.

| № | Задача | Оценка | Как делаем |
|---|--------|--------|-----------|
| 1.1 | Генерация КB под любой план (стандарт/ручной/из шаблона) | **[ЕСТЬ]** | `start_generation(plan, positions=_plan_positions(id))` уже принимает любой plan_id |
| 1.2 | Привязка «план → этап → подэтап → документы» + показ в UI | **[S]** | вывести из `documents` (stage_ids/substages) ∩ подэтапы плана; новый эндпоинт `GET /plans/{id}/coverage` |
| 1.3 | Покрытие плана документами: где есть/нет чанков, что догрузить | **[S]** | тот же coverage: по каждому подэтапу плана — есть ли чанки; агрегат «достаточно/не хватает» |
| 1.4 | Чек-сумма плана: не перегенерировать, если не менялся | **[S]** | sha256 от нормализованного JSON плана → колонка `plan_schedules.src_hash`; sha256 для документов уже есть |
| 1.5 | Авто-обновление при изменении плана: регенерить только затронутые подэтапы | **[M]** | в `save_plan` diff подэтапов → `generate-missing` по изменённым (частичная регенерация уже есть) |
| 1.6 | Удаление плана → удалить/деактивировать его расписания | **[S]** | `delete_schedule` уже есть; довесить каскад при удалении плана |
| 1.7 | Кнопка «перегенерировать KB для плана» (без массовой регенерации без подтверждения) | **[ЕСТЬ/S]** | кнопка генерации во вкладке «Тексты плана» уже есть; добавить confirm на «все планы» |
| 1.8 | Убрать отладку из основного UI (разнесение по подэтапам — под спойлер) | **[S]** | детали doc-breakdown/board живут в `/globaltest`; в основном экране — только «достаточно / не хватает» |

**Итого блок 1:** архитектурно почти готово. Реальная работа — `coverage`-эндпоинт (1.2/1.3),
чек-суммы (1.4) и авто-регенерация по diff (1.5). Остальное — мелочь/уже есть.

## Блок 2. Кэш и индексация вопросов пользователей

**Как устроено сейчас:** `rag.py` — вопрос → `resolve_question` → `route_substages`
(LLM размечает вопрос подэтапами каталога) → `fetch_by_substages` (чанки) →
`generate_answer` (DeepSeek). **Векторного поиска нет** — Qdrant/bge удалены осознанно
([config.py:99](../config.py)). У DeepSeek нет embeddings-эндпоинта.

| № | Задача | Оценка | Как делаем |
|---|--------|--------|-----------|
| 2.1 | Сохранять Q&A: исходный/нормализованный вопрос, ответ, контекст (роль, подразделение, план, подэтапы, документы), время, источник (ai/cache/manual), статус | **[M]** | новая таблица `qa_cache`; `questions.record` расширить |
| 2.2 | Индекс по хешу нормализованного текста (точное совпадение) | **[S]** | normalize (lower, trim, убрать пунктуацию/стоп-слова) → sha256 → уникальный ключ |
| 2.3 | Индекс по ключевым словам | **[S]** | Postgres `pg_trgm` / `to_tsvector` — без ML |
| 2.4 | Учёт контекста (подразделение/план дают разные ответы) | **[S]** | ключ кэша = hash(норм. вопрос + подразделение + plan_id); ретрив уже знает подэтапы |
| 2.5 | Алгоритм: хеш-хит → отдать; иначе близкие по подэтапам+ключам → отдать/адаптировать; иначе AI + сохранить | **[M]** | «похожесть» через общий набор подэтапов из `route_substages` + trgm, **без эмбеддингов** |
| 2.6 | Инвалидация: изменились документы/план → пометить ответы устаревшими | **[M]** | в записи хранить набор sha256 использованных чанков + `plan.src_hash`; при реиндексе/правке — сверка → `stale` |
| 2.7 | ПДн: не хранить в открытом виде, обезличивать перед сохранением | **[S]** | regex-маскирование ФИО/телефона/email → плейсхолдеры перед записью |
| 2.8 | Метрики в админке: топ вопросов, без ответа, на проверку, hit-rate, экономия токенов; правка эталонных ответов | **[M]** | `questions.record` уже логирует эскалации/без-ответа — расширить экран |
| 2.9 | Семантический поиск на эмбеддингах + pgvector | **[ОТЛОЖИТЬ]** | требует вернуть провайдера эмбеддингов (реверс решения). 2.2–2.5 уже дают кэш и «похожие». Включать только если trgm+подэтапы не тянут перефразы |

**Итого блок 2:** таблица `qa_cache` + хеш-кэш (2.2) + инвалидация по хешам документов (2.6) —
основной эффект по токенам/скорости. Эмбеддинги не нужны на старте.

## Блок 4. Качество генерации текстов

**Как устроено:** `GENERATE_SYSTEM` ([planner.py:721](../planner.py)) уже несёт краткость,
запрет дублей, вынос деталей в `hr_note`, per-подэтап структуру из `focus`
(`stage_catalog.json`). Проблема — недожатый промпт + нет пост-проверок.

| № | Задача | Оценка | Как делаем |
|---|--------|--------|-----------|
| 4.1 | Аудит промптов, типовые дефекты | **[S]** | разово на соцпакет/СИЗ/безопасность |
| 4.2 | Запрет кодов транзакций (SAP/ZSIZ), названий внутр. систем → в `hr_note` | **[S]** | +правило в `GENERATE_SYSTEM` |
| 4.3 | Запрет «уточните у HR / см. Приложение N» в теле; только конкретика или удалить | **[S]** | +правило; отсылки допустимы лишь в `hr_note` |
| 4.5 | Хард-кап длины: превышение → флаг `too_long` (не резать вслепую) | **[S]** | пост-проверка в `_build_unified_content`, бейдж в «Тексты плана» |
| 4.6 | Структура по умолчанию (1–2 предл. вводка + 3–6 пунктов) там, где `focus` пуст | **[S]** | добить пустые `focus.structure` |
| 4.7 | Few-shot: 1 хороший + 1 плохой пример в промпт | **[M]** | из обратной связи (соцпакет, культура безопасности) |
| 4.4 / 4.8 | Дедуп абзацев/пунктов | **[M]** | лексически: нормализованное перекрытие слов ≥ порога → флаг/переформулировка. **НЕ эмбеддинги** |
| 4.9 | Ручная правка эталонного ответа в админке + сохранение как образец | **[M-L]** | проверить наличие редактора текста подэтапа; иначе добавить |
| 4.10 | Приёмка на реальных примерах | **[S]** | сверка с требованиями блока 5 |

### Блок 5. Обязательные правила (в промпт / пост-проверку)
1. Без повторов (резюме ≠ дословный повтор).
2. Тех-детали — только если помогают действию; иначе в `hr_note`.
3. Минимум отсылок: конкретный шаг вместо «уточните у HR».
4. Структура: 1–2 предл. + 3–6 пунктов + опц. контакт наставника.
5. Язык простой, без канцелярита.
6. Объём ≤ 1000–1200 симв. (если этап не требует иного) → **4.5**.
