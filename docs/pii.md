# Персональные данные и DeepSeek

**Принцип:** всё, что дошло до внешней модели, считаем утёкшим. Поэтому ПДн маскируются
**до** отправки, в одной точке — `deepseek.chat`. Через неё идут все вызовы модели:
разметка документов, генерация сообщений, ответы на вопросы, разбор штатки.

## Как устроено (`pii.py`)

```
текст → Masker.mask → «Звонить [ФИО_1], тел. [ТЕЛ_1]» → DeepSeek → ответ с метками → Masker.unmask → реальные данные
```

- Одинаковое значение внутри запроса получает одну метку, поэтому модель понимает, что это один человек.
- Обратная подстановка восстанавливает данные в ответе (сообщение сотруднику
  с телефоном отдела кадров остаётся полезным), при этом модель их не видела.
- Таблица меток живёт только в памяти на время одного запроса. Нигде не хранится.
- Выключатель: `NEIROMASTER_PII_MASK=0` (например, чтобы сравнить качество).

| Тип | Метка | Как ловим |
|---|---|---|
| ФИО | `[ФИО_n]` | 2–4 слова с заглавной, из словаря имён/отчеств/фамилий (`data/name_dict`, 71 тыс. слов). **В любом падеже**: «назначить Петрову Анну Сергеевну», «поручить Иванову Ивану Ивановичу», «с Сидоровым Петром» — окончание снимается и слово сверяется со словарём. «Иванов И.И.», «И.И. Иванов» |
| Телефон | `[ТЕЛ_n]` | +7/8 и ещё 10 цифр в любой группировке — мобильные и городские с кодом 3–5 цифр («8 (3452) 56-78-90»); «(3452) 56-78-90» без восьмёрки |
| Email | `[EMAIL_n]` | regex |
| ИНН, КПП, ОГРН, БИК, ОКПО | `[РЕКВ_n]` | число после ключевого слова |
| Расчётный/корр. счёт | `[СЧЁТ_n]` | 20 цифр |
| Банковская карта | `[КАРТА_n]` | 16 цифр (с пробелами или без) |
| СНИЛС | `[СНИЛС_n]` | XXX-XXX-XXX XX |
| Паспорт | `[ПАСПОРТ_n]` | серия/номер после слова «паспорт», в т.ч. «серия 4512 номер 123456» |
| Дата рождения | `[ДАТА_n]` | после «дата рождения», «родился», «д.р.»; «15.03.1990 г.р.» |
| Домашний адрес | `[АДРЕС_n]` | улица, дом и **квартира** (адреса организаций без квартиры не трогаем — они нужны в сообщениях) |
| Табельный номер | `[ТАБ_n]` | число после «табельный номер», «таб. №» |
| Организации | `[ОРГ_n]` | ООО/АО/ПАО/ЗАО/ОАО/ИП/ФГУП/МУП «Название» — в кавычках и без |

**Проверка на ложные срабатывания.** Маскировщик прогнан по всем русским текстам каталога
этапов и базы знаний (~155 тыс. символов: названия, описания, «Главному инженеру»,
«Средства Индивидуальной Защиты», суммы, номера приказов) — ноль ложных «ФИО». Одно слово
в косвенном падеже, похожее на имя, само по себе не считается человеком: нужно слово из
словаря как есть, либо два слова после снятия падежа, либо отчество.

**Обратная подстановка** устойчива к ответам модели:
- в JSON-ответе значение вставляется JSON-экранированным — `ООО "Ромашка"` больше не ломает
  разбор ответа (раньше сгенерированное сообщение в таком случае портилось);
- слегка искажённые метки (`[ФИО 1]`, `ФИО_1`) тоже возвращаются к реальным значениям —
  сотрудник не получит сообщение с техническими метками;
- метка, которой не было в запросе, остаётся как есть.

**Модели подсказано**, что метки — это данные: разбор штатки понимает, что `[ФИО_1]` — человек,
а столбец с метками `[ФИО_n]` — столбец ФИО.

## Методы, которые рассматривали

| Метод | Плюсы | Минусы | Решение |
|---|---|---|---|
| Regex + словарь (сделано) | Быстро, без зависимостей, предсказуемо, покрывает типовые форматы документов | Не ловит ФИО без словарного слова, названия без кавычек, адреса | База: закрывает основной объём сразу |
| NER (Natasha/Slovnet, spaCy ru, DeepPavlov) | Ловит имена/организации/адреса по контексту | +100–500 МБ моделей, CPU-время на каждый запрос, ложные срабатывания | Следующий шаг: подключается в `pii._find_spans` без изменений остального кода |
| Microsoft Presidio | Готовый каркас: распознаватели и анонимизация | Русского из коробки нет, нужен NER под ним | Не нужен: каркас у нас уже есть |
| Своя LLM-модель на сервере | Лучше всего по качеству | Вернули бы локальную LLM, от которой ушли | Нет |

**Рекомендация (открытый вопрос бэклога):** комбинация regex + NER. Regex уже работает.
NER стоит добавить, когда на реальных документах заказчика будет видно, что пропускается.
Проверка: `pii.mask(text)` на выборке документов, глазами.

## «Очищенные копии отдельно»

Отдельная папка с очищенными копиями не нужна: маскирование идёт на лету при каждой
отправке, поэтому в модель физически не может уйти неочищенный текст. Даже если кто-то
добавит новый вызов, он пройдёт через `deepseek.chat`. Хранить вторую копию каждого документа
означало бы дублировать данные и следить за их синхронизацией.

## Чувствительные документы (положение о зарплате и т.п.) — сделано

Маскирование скрывает людей и реквизиты, а суммы и условия — нет. Поэтому у документа есть
флаг **«Не отправлять в ИИ»**:

- при загрузке — галочка «Конфиденциальный документ — не отправлять в ИИ» под зоной загрузки;
- у уже загруженного — кнопка «Не отправлять в ИИ» / «Разрешить ИИ» в списке документов
  (`POST /documents/{имя}/confidential`).

Что происходит: файл хранится в базе, но не размечается и не отправляется в модель вовсе.
Если разметка уже была, она удаляется — фрагменты документа больше не попадают ни в сообщения
плана, ни в ответы на вопросы; сообщения, которые на него опирались, автоматически
обновляются без него. Сообщение по такой теме администратор пишет сам («Редактировать» на
вкладке «Сообщения»), а вопросы по ней уходят человеку через очередь вопросов.

Какие документы считать чувствительными — решение заказчика; технически флаг работает
для любого документа.

## Где проверить

- `python -m pytest -q test_pii.py` — типы данных, падежи, ложные срабатывания, обратная подстановка;
- `python -c "import pii; print(pii.mask(open('doc.txt').read()))"` — глазами на реальном документе.
