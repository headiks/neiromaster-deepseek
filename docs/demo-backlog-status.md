## 3. Сообщения и экономия токенов

**Почему на демо ушло ~600 тыс. токенов (372 запроса).** 372 = 62 подэтапа полного плана ×
6 расписаний (5 должностей + общее). Кнопка «Перегенерировать» (`/generate` без
`only_missing`) заново гнала **каждый** подэтап под **каждую** должность, ничего не сверяя:
пропуск уже готового работал только в «Догенерировать недостающие». Каждый запрос нёс до
24 000 символов фрагментов документов, отсюда ≈1 600 токенов на запрос.

| Задача | Статус |
|---|---|
| [крит] Контрольные суммы перед генерацией; не менялось — ни одного запроса | ✅ у каждого сообщения SHA-256 **отпечаток входов**: версия промпта, этап/подэтап/тип/описание, должность и сами фрагменты документов. Совпал — модель не зовётся, ответ «Всё актуально». (Для документов уже был SHA-256, MD5 в проекте не было) |
| [крит] То же для «Перегенерировать сообщения» | ✅ одна кнопка «Обновить сообщения плана», всегда инкрементальная |
| [крит] Инкрементальная перегенерация | ✅ изменился документ, описание подэтапа или должность — переписываются только затронутые сообщения |
| [крит] Разобраться с 600 тыс. | ✅ см. выше; расход теперь виден в `GET /api/llm-usage` (по дням, из `usage` ответа DeepSeek) |
| Защита от многократных нажатий | ✅ кнопка блокируется; на сервере одна генерация на план (повторный запуск подхватывает идущую); перед запуском показывается, сколько запросов будет, и больше 5 — только с подтверждением |

## Что важно при выкатке

- Схема БД обновится сама при старте (новые колонки `users.phone/email/temp_password`, индексы).
- Уже сгенерированные сообщения без отпечатка считаются актуальными: первый запуск
  после выкатки **не** перегенерирует всё заново.
- Меняете промпты генерации так, что старые тексты нужно переписать: увеличьте
  `planner.GEN_PROMPT_VERSION`.
- Проверьте маскирование на реальных документах заказчика: `python -c "import pii; print(pii.mask(open('doc.txt').read()))"`.
- Новый React-фронтенд (`frontend/`) не обновлялся: боевой интерфейс — `static/`.
